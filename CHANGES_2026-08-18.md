# What I checked and fixed — Aug 18, 2026

I unzipped this, ran `npm install`, actually started the server, and drove real
requests through it (login, client creation, and a full chatbot → dashboard
lead flow) rather than just reading the code. Here's what I found.

## Fixed: chatbot → dashboard bridge was silently broken

**The bug:** `SETUP_FOR_CLIENT.md` tells you to set `WEBHOOK_SECRET`, and
correctly warns you to *never* put that secret inside the chatbot HTML (it's
public, client-side code — anyone can view-source it). But `server.js` required
that exact secret on `/api/bridge/conversation` and `/api/bridge/lead`, and the
chatbot HTML never sent it. So the moment you followed the setup instructions
properly, every message and lead from the chatbot would fail with 401 and
just... vanish. No error shown to you or the visitor — the chat would keep
working, your dashboard would just quietly stay empty.

**The fix:** `WEBHOOK_SECRET` is still required for `/api/leads` (that route is
for trusted server-to-server integrations like Tally/Zapier, which *can* hold a
secret). The two bridge routes now rely on rate limiting instead (already
present in the code — 120 req/min for conversation events, 60/min for lead
submits), the same trust model already used for `/api/public/client-config`.
This is the standard pattern for public lead-capture endpoints.

I verified the fix live: sent a chat message and a completed lead through
`/api/bridge/*` with no secret header, logged into the dashboard, and confirmed
the lead appeared correctly — scored 85/100, marked HOT, with UTM source intact.

## Which chatbot HTML file to actually use

There are two chatbot files and they are **not** duplicates:

- **`ASSISTQ_Chatbot_CLIENT_READY_v7.html`** — the one to use. Supports
  `?clientId=&dashboardUrl=` URL params (so one file serves multiple clients,
  per `SETUP_FOR_CLIENT.md` Part E), and pulls the assistant name/greeting/
  questions live from the dashboard via `/api/public/client-config` — meaning
  you can edit a client's bot in **Client Setup** without touching any HTML.
- `ASSISTQ_Chatbot_Connected.html` — an older, single-client demo version with
  everything hardcoded. `CHATBOT_CONNECTION.md` currently points you at this
  one; for anything beyond local testing, use the v7 file instead.

## Fixed (this pass): Keywords tab was crashing

**The bug:** In `public/app.js`, the Keywords page tried to read
`d.gsc.connected` to decide what message to show under "Raw Search Console
queries" — but `d` was never defined in that function (only `g`, which held
just the row array, not the whole gsc object). For any brand-new client with
no Search Console data synced yet — which is every client on day one — this
threw a JavaScript error the moment you opened Keywords, and the tab would
appear to do nothing / stay blank.

**The fix:** Changed `d.gsc.connected` to `S.data.gsc.connected`, the correct
reference to the client's Search Console connection state. Verified by
simulating the render function with an empty keywords/gsc data set (the
default state) — it now renders without error.
